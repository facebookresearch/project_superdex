# Asset Tuner

SuperDex Asset Tuner is a physics workbench of sorts that is used primarily for tuning and calibrating various physics parameters related to rigid bodies and articulations in a prefab (`.superdex_prefab`) or a [scene](./scene_editor.mdx) (`.superdex_scene`). In a scene, the tuner can also script the robots through their controllers and judge each run against a task's success and failure criteria. The tuner is designed to run repeated experiments with boundary conditions (loads) on the same prefab/scene multiple times with different parameters (overrides) to achieve the desired behavior.

**For a more illustrative example:** if we have an ethernet port and jack pair, and we have measured that it requires 7 Newtons of force to plug in an ethernet jack, we can set up a prefab scene containing both assets and a 7 N ramp of force pressing in the jack. Then we dial in the contact parameters and latch's spring stiffness by observing how far the jack enters the port.

:::warning Experimental
Scene support is currently experimental, so its fields and behavior may still change.
:::

## What Is an Asset Tuner?

An asset tuner is a `.superdex_tuner` file, written as JSON, that references a prefab or a scene and describes one experiment on it:

| Part | What it does |
|------|--------------|
| **Loads** | Forces, torques, joint efforts, and pose paths applied to the prefab, each with a profile over time, and, in a scene, controller inputs that script its robots. |
| **Probes** | What to measure every step: body poses and velocities, relative poses, joint states, contact forces, penetration, and solver statistics. |
| **Task** | Scene tuners only: a `.superdex_task` whose objects start the run and whose success and failure criteria decide it. |
| **Prefab Overrides** | Values changed on the prefab, or on a task's objects, for each run, without editing the prefab file. |
| **Stop Conditions** | End a run early, for example when a part falls or leaves a box. |
| **Run Settings** | Time step, duration, gravity, and the ground plane. |

A tuner runs the same way from the [command line](#command-line), with the
`superdex_asset_tuner` tool, so a script or an agent can sweep parameters over an
experiment you set up in Studio. Studio and the command line write the same
recordings.

:::note Note
Asset Tuner does not modify the prefab or scene directly, so you must migrate the desired changes to the respective prefab or scene yourself.
:::

## Creating an Asset Tuner

Right-click a prefab or scene in the Asset Browser and choose **Create Asset Tuner...**. Studio creates `<prefab or scene>_tuner.superdex_tuner` beside it. Double-click an existing `.superdex_tuner` to open it.

## Editor Windows

| Window | What you do there |
|--------|-------------------|
| **Asset Tuner Loads** | Add and edit loads. |
| **Asset Tuner Prefab Hierarchy** | The prefab's actors, read-only. Click a row to select it in the viewport. Unused a scene tuner. |
| **Asset Tuner Run** | The prefab or scene, the task and the controllers it drives, recording, run settings, probes, solver overrides, and stop conditions. |
| **Asset Tuner Plots** | Live plots of every channel, and the list of previous runs. |
| **Asset Tuner Prefab Overrides** | Values to override on the prefab for each run. |
| **Physics Settings** | Debug draw for this editor. The time step, gravity, and ground come from **Asset Tuner Run**, and the solver from the prefab or scene, so a Studio run matches the command line. |

Play, pause, step, and stop with the viewport controls, as in any other [physics-enabled editor](./user_interface.mdx#simulating-physics). Each Play resets the scene or prefab.

Any window missing may be accessed from the Windows menu. You can also use Window -> Reset Layout to open windows in the layout that they are designed with.

## Loads

Choose a type from **+ Add Load** at the bottom of **Asset Tuner Loads**. If a
body is selected in the viewport, the new load targets it.

| Load | What it applies | Target |
|------|-----------------|--------|
| **Force** | A force at a point. A point away from the center of mass also applies the matching torque. | A dynamic rigid body or an articulated link |
| **Torque** | A pure torque. | A dynamic rigid body or an articulated link |
| **Joint Effort** | A generalized force on a joint's degrees of freedom, in N for prismatic and N·m for revolute joints. | A joint |
| **Pose Path** | A spring-damper that pulls a grab point on the body along timed waypoints, and optionally turns the body with them, like force-dragging it in the viewport. | A dynamic rigid body or an articulated link |
| **Controller Input** | Moves a robot controller's input over time: a tool pose along timed waypoints, or joint positions along timed keys. Scene tuners only; see [Controller Inputs](#controller-inputs). | A bot's controller, as `bot/controller` |

Each load is presented as a card. A collapsed card shows a small preview of its profile over the run. You can enable and disabled loads using the checkbox or delete them using the trashcan button.

- **Frame** chooses how the direction behaves: **World** keeps the **direction** fixed in the
  world while the point follows the body, **Local** turns it with the body, and
  **World-Fixed** (forces only) fixes both the direction and the point in the
  world.
- **Point** is where a force acts. Press **Pick Point** and click the body in
  the viewport to set both the target and the point, or **Center of Mass** to
  use the body's center of mass.
- **Profile** sets the magnitude over time: **Constant**, **Envelope** (rise,
  hold, and fall), **Sine**, or **Keyframes**. Keyframes can also animate a
  load's direction and point.
- **Pose Path** loads replace the profile with a waypoint table and a timeline.
  **Add Waypoint** appends one, **Set to Current Pose** captures the body's pose
  into the selected waypoint, and each span between waypoints can drive the
  pose, the position only, or release the body. The **Drive** settings set how
  stiffly the path is followed, and **Max Pull Force Prediction** estimates the
  force it can exert.

Selecting a card selects its load in the viewport, where it is drawn as an
arrow in its type's color. A transform gizmo on the selected load moves its
point and turns its direction, or moves the selected waypoint of a pose path.
Most load edits apply live while the simulation runs; adding, removing,
renaming, reordering, or retargeting a load applies on the next run.

### Controller Inputs

In a scene tuner, every bot controller that takes a float input is stepped with the simulation. A **Controller Input** load scripts one of them; a controller without one holds where it starts, so its robot holds its initial pose. Only one enabled load can drive a controller. **Asset Tuner Run** lists each controller with the load that drives it; click the load to open its card.

The card edits what the controller's input takes:

- A **tool pose** (for example, an operational-space controller) follows a list of
  waypoints in the bot's root frame. The viewport draws the tool's path with each
  waypoint's time, and the gizmo moves the selected waypoint. While a run plays,
  it also shows how far the tool is from its target.
- **Joint positions** follow a list of keys, with a slider per joint within its
  limits (revolute joints in degrees). Joints not listed hold their initial joint positions.

**Add Waypoint** and **Add Key** append one after the last; while simulating, they take the current pose. **Set to Current Pose** sets the selected waypoint or key to where the tool or joints are: live while simulating, else where they start. Changing a load's type to or from Controller Input clears its waypoints and keys.

### Timeline

The Timeline, pinned above the load cards, has a row of keys for every keyed load: **Keyframes** profiles, pose paths, and controller inputs. Click a key to select it and open its card, or drag it to retime it. Scroll to zoom in time, drag with the right mouse button to pan, and double-click to see the whole run.

A scene tuner's Timeline also has a playhead (white). Click or drag the strip to move it. Clicking a key moves the playhead to that key, and Play and Step move it, but opening a load card does not. **At Playhead** on a controller card adds a waypoint or key at the playhead.

A translucent robot is shown in the viewport for estimating the intended pose of the robot. Note that for tool or end-effector based targets, the pose is only estimated from inverse kinematics and is most likely not representative of the final pose.

## Probes and Plots

Probes are added from **Asset Tuner Run → Probes**. Each probe produces one or
more **channels**, sampled every step, and every load also produces its own
magnitude channel, `load.<name>.mag`.

| Probe | Channels |
|-------|----------|
| **Body Pose** | Position and rotation of a body, in the world frame. |
| **Body Velocity** | Linear and angular velocity of a body. |
| **Joint State** | Position and velocity of each of a joint's degrees of freedom. |
| **Contact Force** | Total contact force on a body. |
| **Penetration** | Approximate volume by which a body overlaps other actors. **Ignore Ground** leaves out the ground plane. |
| **Relative Pose** | Position and rotation of a body in the frame of another body or link (**Frame**), for example an object in a gripper. |
| **Solver Stats** | Nonlinear iterations, residual, line-search iterations, and convergence of each step. |
| **Performance** | Wall-clock solve time of each step. This varies between runs. |

**Asset Tuner Plots** lists every channel. Tick a channel to plot it, or drag
channels onto a plot area to group them; **+ Add Plot** adds another plot area,
and dropping channels onto the empty space below the plots makes one. All plots
share one time axis, so they pan and zoom together. **Auto-fit All** keeps them
framed, and **Clear** empties every plot.

Previous runs stay in the plots, faded behind the current one, so you can see
what a change did. The **Runs** list shows each run; hover one to see what
changed in the tuner since the run before it. Untick a run to hide it, pin it
to keep it, or delete it. **Runs Kept** sets how many unpinned runs are kept,
and **Clear Runs** forgets all unpinned runs.

## Prefab Overrides

**Asset Tuner Prefab Overrides** changes values on the prefab before each Play,
without touching the prefab file. Each override is a **Path** into the prefab's
JSON and a **Value**:

```text
actors.rigid[name=block].contact.coulombFrictionCoefficient = 0.8
prefabs[name=Nested1].actors.rigid[name=Rigid1].isStatic = true
```

`[index]` and `[name=...]` pick an element of a list. An override that does not
apply to the prefab turns red and explains why. Overrides apply on the next
Play; the viewport always shows the unmodified prefab.

In a scene tuner, overrides change the task's objects instead: every one of
them, so each path must fit every object's prefab.

## Scenes and Tasks

The **Prefab or Scene** slot at the top of **Asset Tuner Run** holds what the
tuner simulates. Pick a prefab or a scene, or drop one from the Asset Browser,
to replace it. Loads, probes, and overrides keep their targets, and the ones
the new prefab or scene does not have show as not found. **Open** opens the
prefab or scene in its own editor. A scene tuner runs the saved scene, and
warns when the scene has unsaved edits.

In a scene, bot actors are named after their bot file, so probes target a
robot's links as `<bot actor>/<link>`.

A scene tuner can also have a **Task**. Pick a `.superdex_task`, or drop one
from the Asset Browser, to stage its objects in the scene; probes target them
as `<spawn>/<actor>`. **Open** opens the task in the
[Scene Editor](./scene_editor.mdx), whose **Task Preview** edits its success
and failure criteria; Play uses the saved task. If the task's objects cannot be
staged, the Task row says why.

The task's criteria decide the run, the same way as on the command line. The
run pauses at the first success or failure, and the viewport banner and the
Task row show the result. With **Stop at Duration** on, a task that has not
succeeded by the end of the run (its duration, or the task's time limit if
sooner) fails too. When the run
is recorded, its `summary.json` status is `succeeded` or `failed`.

For an example, open `assets/tasks/box_and_blocks/pick_place_red.superdex_tuner`.
It scripts an FR3 with a 2F-85 gripper to pick the red block out of one
compartment of the Box and Block Test box and place it in the other. It runs
on `box_and_blocks.superdex_scene` and is judged by `box_and_blocks.superdex_task`.

## Stop Conditions

A stop condition pauses a run when it triggers, shows a banner in the viewport,
and records why the run ended. Add one from **Asset Tuner Run → Stop
Conditions**:

| Condition | Stops when |
|-----------|------------|
| **Leaves Box** | A body's origin leaves a box. |
| **Enters Box** | A body's origin enters a box. |
| **Falls Below Height** | A body falls below a height. |
| **Interpenetration** | A body's penetration volume rises above a threshold. |
| **Channel Threshold** | Any channel goes above or below a value. |

Box conditions draw their box in the viewport. Select the condition to move the
box with the gizmo (`W`) or resize it (`R`), or press **Center on Target**. A
condition can wait for a start time, to let the scene settle, and can require
the condition to hold for a while before it triggers. Stop condition changes
apply on the next run.

## Recording Runs

**Asset Tuner Run → Recording** writes runs to disk. Press **Record** while a
run plays to record it, or while stopped to arm recording for every run from
the next Play; press it again to stop and disarm. Each recording creates a
timestamped folder (`<UTC timestamp>_<tunerName>`, with an optional run tag)
in **Output Folder** holding the resolved tuner (`tuner.resolved.json`), every
channel as `signals.csv` (a `t` column plus one column per channel), and a `summary.json` (per-channel
min/max/final, whether `sim.rrd` was written, and a task's result). When simulation recording is
enabled, the default Studio build also writes `sim.rrd`, a Rerun recording of
the simulation. A source build with `-DSUPERDEX_BUILD_RECORDER=OFF` still writes
the other run files. **Stop at Duration** pauses the run and ends its recording
at the run's duration. **Last Run** and **Copy Path** point at the most recent
folder.

## Command Line

`superdex_asset_tuner` runs a saved tuner without Studio, which is useful for
repeatable comparisons once the loads and probes are set up:

```bash
superdex_asset_tuner describe experiment.superdex_tuner
superdex_asset_tuner run experiment.superdex_tuner --out tuner_runs
superdex_asset_tuner run experiment.superdex_tuner --set 'loads[name=push].profile.magnitude=7' --out tuner_runs --tag force_7n
```

Run `describe` first to list what loads, probes, and stop conditions can
target, **after** prefab overrides. Names in nested prefabs are paths, such as
`fixture/brick`, and articulated links are `arm/link2`. `--set` changes an
existing field of the tuner for one run, not the file; it cannot append an
array entry.

`run` prints the run's summary and writes the same run folder as a Studio
recording; `--no-files` prints the summary only. A `stopped` status means a
stop condition ended the run, not that the simulation failed: the summary says
which condition fired.

The [Asset Tuner source guide](https://github.com/facebookresearch/project_superdex/tree/main/superdex_asset_tuner)
covers the command line and the full `.superdex_tuner` schema.
