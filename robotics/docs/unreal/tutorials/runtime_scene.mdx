# Tutorial: Load a Scene File at Runtime

Run a `.superdex_scene` file in SuperDex Unreal without importing it: the file becomes the physics
scene, and a level mirrors it. For how this differs from an editor-authored level, see
[Runtime Scene Loading](../runtime_loading.mdx).

:::warning What this tutorial does not cover
Nothing in the plugins creates the scene's bots or drives them from tracked hands: that takes C++
in your project (see [Driving the scene's bots](../runtime_loading.mdx#driving-the-scenes-bots)),
and no supported example of it ships. This tutorial loads a scene and shows its base scene and
prefabs simulating.
:::

## 1. Get a scene file

Use any `.superdex_scene` or `.superdex_scene_archive`, for example one authored in the
<ProjectSuperdexLink site="studio" path="docs/bot_scene_editor/">SuperDex Studio Bot Scene Editor</ProjectSuperdexLink>. An archive is
self-contained, which makes it the easier file to move between machines.

You can also export one from an editor-authored level. In a level's Event Graph (for example on a
key press), call `ExportSuperDexBotScene` with an `ExportName` and an `OutputDir`, then play
the level in the editor and trigger it. It writes `<OutputDir>.superdex_scene_archive`, pausing
the simulation while it exports.

## 2. Make a viewer level

Create a new level for viewing the scene. It must not contain SuperDex Physics components or a
`MochiSceneSettingsActor`: the scene file is the only source of physics actors and settings, and
the load fails if the physics scene already holds actors. Then:

1. Add lights and a sky.
2. Add an empty actor, and add a `SuperDexBotSceneVisualizationComponent` to it.
3. Save the level, for example as `/Game/L_SceneViewer`.

## 3. Launch with the scene

Pass the scene with `-SuperDexSceneFile=`, using an absolute path. From the editor executable:

```bat
"%UE_ROOT%\Engine\Binaries\Win64\UnrealEditor.exe" "%CD%\SuperDexUnreal.uproject" /Game/L_SceneViewer -game -SuperDexSceneFile="C:\scenes\my_scene.superdex_scene_archive"
```

Launching the editor itself with `-SuperDexSceneFile=` also works: each **Play** session then
loads the file. For a packaged build, add the level to `MapsToCook` and pass the same argument to
the packaged executable.

## 4. Check the load

The output log reports the result:

- `SuperDexBotSceneSubsystem: loaded '<path>' - <N> actors, <M> bots declared with <K> controllers (none initialized yet)`
  means the scene is live. The visualization builds its meshes, from the file's `.glb` render
  models where it has them; add `-NoRenderModels` to draw collision shapes instead.
- `SuperDexBotSceneSubsystem: failed to load '<path>': <reason>` means it is not. The session
  then runs without physics rather than falling back to the level's own.
